# DR-0011: Campaigns (parameter sweeps)
Status: Accepted (2026-10-13); amendment proposed (2026-10-16)

The only autonomous mode. A campaign spec is approved once, then runs without the user.

Spec (engine/campaigns/<id>/campaign.yaml): parameter grid, target machine, job template, metrics to
collect, success/failure definition per run, retry policy for transient failures, node-hour budget,
notification channel.

Execution: deterministic code, no LLM inside the loop. Prefer scheduler-native orchestration (job arrays,
`afterok` dependencies, scheduler mail) or the headless engine on the workstation. An agent may author the
spec and analyze the results; it may not change the spec mid-run. Budget exhaustion stops the campaign.
Results land in evidence/ via the executor; a first-pass summary is generated by parsers, then optionally
reviewed by an analysis agent.

## Amendment (2026-10-16, proposed with M9.1): a campaign is a job
These implementation choices differ from the text above. Merging the M9.1 PR accepts them.
- **Spec location:** a `campaign` section in the experiment's `job.json` (`experiments/EXP-NNN/`), not
  `engine/campaigns/<id>/campaign.yaml`. A campaign follows the same path as every job (DR-0006): `jobs.submit`,
  lint, approval card, launch, fetch into `evidence/raw/`.
  - One approval covers the whole grid.
  - A campaign never auto-approves, whoever proposed it.
  - Either an agent (`jobs.submit`) or the user (`re job propose`) can write one. `re job propose` commits exactly
    the proposed files to `experiments/EXP-NNN/` as the user's work. Agents' experiments arrive on their branches.
  - The approved files are fingerprinted, and the driver is generated from them at launch, so the spec cannot
    change mid-run.
- **Grid:** `parameters` maps each name to its values. Every combination is a point, the first parameter varying
  slowest, at most 1000 points.
  - Names match `[A-Za-z][A-Za-z0-9_]*`. Values are numbers or short tokens (`[A-Za-z0-9_.:+-]`, at most 64
    characters), so they reach the script as `P_<name>` environment variables with no quoting risk.
  - Each point runs in `points/NNNN/` with a copy of the experiment's files.
- **Budget:** `resources.walltime` is the campaign's wall-clock budget. On a workstation, node-hours are walltime
  times one node.
  - No point starts unless it could finish (its `point_walltime` plus 30 s) within the budget.
  - The runner's watchdog stops everything at the budget.
- **Success per point:** exit code 0 within `point_walltime`.
  - A failed point is retried up to `retries` times (0–3). Transient and permanent failures are not yet told
    apart.
  - A point that overruns its time has its process tree stopped and is marked `timeout`.
- **Metrics and the first-pass summary:**
  - `campaign.csv` has one row per point: the values, status, exit code, attempts, and seconds.
  - Every CSV output is merged across points into `campaign-<output>.csv`, with the point and its values in
    front. That merged file is the first pass; parsers come later.
- **Where it runs:** on machines without a scheduler only, for now. A generated bash driver (`.cairn/campaign.sh`,
  bash 3.2 compatible) runs inside the normal workstation runner, so no engine and no model run on the
  workstation. Slurm job arrays come next.
- **Evidence integrity:** an experiment file may not sit where the campaign writes (`points/…`, `campaign.csv`,
  `campaign-*.csv`) and may not be a declared output. Every point's outputs therefore come from its own run.
  The driver reads results only from regular, single-link files inside the job directory (as fetch does). It
  removes a file before writing it, so a link a point leaves behind cannot make the driver read or write outside
  the job.
- **Reconcile on wake:** `re job reconcile` (and `POST /api/jobs/reconcile`) asks the machines about every
  unfinished job and fetches finished campaigns into the evidence.
  - If the SSH session did not survive the sleep, the jobs are reported as waiting (exit 3).
  - The user reopens the session (the human gate) and runs reconcile again.
- **Notification:** not yet. It comes with the notify MCP server (the rest of M8). Meanwhile the approval card
  shows the expected duration.
